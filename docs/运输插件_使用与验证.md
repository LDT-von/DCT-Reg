# DCT 运输插件：使用与验证

现在可以把同一个运输模块接到 MCAT 和 SurvPath 的双模态特征之间。两种接口已经接通，尚未进行真实患者训练，因此目前可以说“实现了可插拔”，还不能说“接到不同模型后都能提高分数”。

本次基于 `530f87b` 增加独立模块和适配器，原 DCT 模型、三解码器配置、训练入口和历史实验均未修改。

## 1. 插在哪里

```text
基线自己的病理编码器 ── 病理 token ──┐
                                      ├─ DCT 运输插件 ── 基线自己的融合层 ── 生存预测
基线自己的组学编码器 ── 通路 token ──┘
                                      └─ 可选三重建分支（训练时计算损失）
```

插件先把两路特征压缩为槽，再映射到两套共享原型坐标。在四个潜在阶段上，分别用余弦、欧氏和正点积成本计算槽间运输；证据门控制运输两侧的边际质量，阶段成本补充槽对的匹配信息。Sinkhorn 得到运输计划后，再校正边际。运输计划与槽内容共同生成事件特征，并形成重心运输特征。

新增的接入部分用注意力把这些特征写回原有 token，再通过可学习的残差系数加入原特征。两侧系数初始化为零，所以完整有效输入下，写回特征初始等于原特征，在 `eval()` 模式下初始预测也与原生模型一致。训练时插件会消耗槽采样和 dropout 的随机数，不能保证随后原生 dropout 的输出逐值相同。它保留输入的 token 数和通道数；基线的融合层和生存预测头继续使用原来的形式。

这里的四个阶段是潜在表示，不直接等同于真实疾病分期或时间区间。运输和重建也不构成因果发现或缺失组学恢复的证明。共享原型、槽、Sinkhorn 和重建已有相关工作，插件化本身不能作为独立的新颖性证明。

## 2. 三条重建分支是什么

| 分支 | 从什么表示重建 | 重建目标 |
|---|---|---|
| 自重建 | 组学槽 | 编码后的组学通路特征 |
| 跨模态重建 | 按同一运输计划搬到组学侧的病理槽 | 编码后的组学通路特征 |
| WSI 重建 | 病理槽 | 编码后的病理 patch 特征 |

三条分支默认使用独立解码器，权重均为 0.05。共享对照仅让自重建和跨模态重建共用解码器，WSI 解码器保持独立。

目标采用：

\[
L = L_{\mathrm{baseline}} + r(e)\left(0.05L_{\mathrm{self}}+0.05L_{\mathrm{cross}}+0.05L_{\mathrm{WSI}}\right),
\qquad r(e)=\min\left(1,\max\left(0,\frac{e-2}{5}\right)\right).
\]

`e` 是从零开始的 epoch：前期权重为零，随后逐步增加，到 `e=7` 达到完整权重。这样先让主任务建立表示，再逐渐增加重建要求。目标特征停止梯度，重建路径仍反向更新编码器、槽和运输。跨模态计划同时使用病理和组学信息，不能将它描述成只看病理的独立组学预测。

WSI 重建的是特征，不是图像像素。其目标查询经过冻结的投影，输出没有目标查询残差直连，避免直接复制目标。损失按患者的有效 token 均值归约，排除 padding；全缺失分支返回可反传的零值。

重建解码器在 `eval()` 下不执行，即使显式要求辅助损失也会跳过。运输核心参与预测，训练后的运输核心被关闭时，预测一般会改变。DCT 原有排序和多样性等额外损失没有自动搬入外部基线；这里保留各基线自己的主任务目标，辅助重建可单独关闭。

## 3. 现成接口

主要文件：

- `survot_rank/plugins/transport/core.py`：独立运输核心，可从当前 DCT 复制特征计算参数。
- `survot_rank/plugins/transport/plugin.py`：保持特征形状的残差接入模块。
- `survot_rank/plugins/transport/reconstruction.py`：可选三重建头。
- `survot_rank/plugins/transport/adapters.py`、`native.py`：MCAT、SurvPath 的原生接口与可运行构造入口。

两种基线的编码后特征都是 256 维。默认原始 WSI 输入为 1536 维：MCAT 在模型实例中将第一层输入宽度调整为 1536，所有实验组采用相同调整；SurvPath 通过原生构造参数设置输入宽度。

原生 MCAT 需要六个组学组；SurvPath 的通路数由数据确定。传入的 `omic_sizes` 必须来自实际分组，并固定通路顺序。两个官方项目都使用 `models` 包名，需要在不同进程运行。原生接口按单患者输入使用；核心插件本身支持批量和有效位掩码，但这两种原生基线的注意力和池化不支持 padding，因此适配器明确拒绝部分缺失的掩码。

### 构造并接入训练

两个 YAML 是模型构造预设，不是原 DCT 训练命令的配置。将下面步骤接到相应基线自己的训练器；`omic_sizes`、输入、标签和主损失来自现有数据管线。

```python
import yaml
from survot_rank.plugins.transport import build_native_adapter

with open("configs/transport_plugin_mcat.yaml", encoding="utf-8") as f:
    recipe = yaml.safe_load(f)
model = build_native_adapter(omic_sizes=omic_sizes, **recipe).to(device)
optimizer = optimizer_class(model.parameters(), **optimizer_kwargs)

model.train()
native_output, auxiliary_loss = model.forward_with_aux(
    **native_inputs, cur_epoch=epoch, plugin_compute_aux=True
)
# MCAT 保留原 hazards/S/Y_hat/attention 四元组；SurvPath 保留原 logits。
main_loss = baseline_loss(native_output, labels)
loss = main_loss + auxiliary_loss  # auxiliary_loss 已包含 ramp 和三个权重
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

`baseline_loss` 表示原生训练器的损失调用，需要保留其标签、删失与输出转换。上面没有把 MCAT 的 hazards 当作 SurvPath 的 logits，也没有把重建系数再次乘入损失。优化器应接收整个适配器的参数，避免只更新原生主干。

MCAT 的 `x_path` 形状为 `[N,1536]`；SurvPath 为 `[1,N,1536]`。组学输入沿用 `x_omic1` 到 `x_omicP` 的单患者一维向量。SurvPath 不需要注意力输出时使用 `return_attn=False`。

构造无辅助分支的组时，设 `reconstruction_config=None`。设 `enabled=False` 可跳过运输和辅助重建；`model.plugin.set_plan_mode("independent")` 可以换成保持证据边际的独立耦合，但正式实验应按生成的各组配置从头训练，不用同一 checkpoint 临时切换来宣称训练收益。

### 保存和恢复

```python
import torch

recipe = dict(model.native_config)
recipe["plugin_config"] = model.plugin.config.to_dict()
recipe["enabled"] = model.plugin.enabled
recipe["reconstruction_config"] = (
    model.plugin.reconstruction.configuration()
    if model.plugin.reconstruction is not None else None
)
torch.save({"recipe": recipe, "state_dict": model.state_dict(),
            "source_provenance": model.source_provenance}, checkpoint_path)

saved = torch.load(checkpoint_path, map_location="cpu", weights_only=True)
restored = build_native_adapter(**saved["recipe"])
restored.load_state_dict(saved["state_dict"], strict=True)
restored.to(device).eval()
```

保存时同时记录通路分组、特征版本、患者划分、主任务训练设置和实际代码 commit。配置必须先恢复再加载参数；重建权重、渐进日程和解码器共享方式不匹配会明确拒绝。若只需继承 DCT 的特征计算，可使用 `TransportCore.from_dct(dct_model)` 和 `TransportReconstructionHeads.from_dct(dct_model)`；这不包含原生生存头，也不说明新接入方式能沿用原模型分数。

## 4. 怎样回答“运输有没有收益”

每种基线生成以下组，并可添加共享解码器对照：

| 组 | 耦合方式 | 三重建 | 作用 |
|---|---|---|---|
| 原生基线 | 插件关闭 | 无 | 原生参考 |
| Independent | 相同证据边际的外积 | 无 | 控制新增结构与特征接入 |
| Learned OT | 学习的运输计划 | 无 | 与 Independent 比较运输匹配本身 |
| Independent + 重建 | 相同证据边际的外积 | 独立三头 | 控制重建带来的收益 |
| Learned OT + 重建 | 学习的运输计划 | 独立三头 | 完整设置，与上一组比较 |
| 可选共享对照 | 学习的运输计划 | 自/跨共享，WSI 独立 | 检验解码器分离的影响 |

Independent 和 Learned OT 保留相同模块、阶段、几何通道和可学习参数，只改变运输计划的计算方式。部分成本参数在 Independent 中保留但不参与计划；因此参数数量相同不表示两组计算量或活跃梯度完全相同。Uniform 另外改变边际，不作为首要的运输匹配对照。

同基线、同种子构造时，主干和运输模块的初始化及构造后的随机状态在辅助分支开关、共享方式之间一致。实际训练仍需核对患者划分、特征、时间分箱、删失定义、优化器、训练轮数和 checkpoint 选择规则。比较各折及多个种子的配对 C-index 差值，同时报告训练/推理时间、显存和模型大小。不同原生基线可以保留各自的合理训练设置，但其内部各组必须匹配。

只有 Learned OT 对 Independent 的匹配训练比较能支持运输匹配的收益；如果完整组仅优于原生模型，仍无法排除新增容量或重建训练的贡献。在 MCAT、SurvPath 都获得可信的配对收益后，才可以说“同一个模块对多个基线有效”。当前 DCT 历史分数不能直接填到新插件的结果表中。

## 5. 生成待运行计划

```text
python scripts/prepare_transport_plugin_experiments.py --help
```

该工具只生成配置和协议清单，不启动训练。使用 `--baseline mcat` 或 `--baseline survpath`，通过 `--omic-sizes` 填入逗号分隔的真实分组宽度，并以 `--output` 指定尚不存在的目录；`--include-shared` 加入共享解码器对照。默认 `both` 对两种基线使用同一组宽度，MCAT 必须恰好六组；若两种基线使用不同分组，应分别生成计划。完整协议未填之前保持待核对状态。现有实验编号和主档未改动。

## 6. 官方源码与检查范围

`third_party/transport_plugin_baselines/` 保留经过校验的官方模型源码子集和来源清单，没有预训练权重或患者数据：MCAT 固定到 `b9cca63be83c67de7f95308d54a58f80b78b0da1`，SurvPath 固定到 `3f73ddd6705ec67d643020c5bb04fb13f9f382cc`。构造入口在导入前校验文件字节、SHA256、Git blob 和原始源码锚点。MCAT 的上游 LICENSE 保留；该 SurvPath 快照没有单独的 LICENSE，清单如实记录来源状态。

小张量检查覆盖官方模型输出一致性、真实编码器梯度、三头与 checkpoint 配置、运输边际、缺失患者、padding、混合精度以及来源校验。重合槽的欧氏距离采用零距离梯度有限的计算方式。独立插件默认边际校正预算为 10000 次，达到容差即提前退出；该上限处理尖锐计划下 1000 次不足的边界情况，不表示每次执行满预算。超过预算仍明确报错，不能改成另一种计划后继续宣称是原 OT。

检查使用模拟输入，不等于患者训练结果、外部基线公平复现或新颖性证明。默认参数保留 FP32，混合精度通过 autocast 使用；不要将运输模型参数整体转换成 FP16。导出已有 DCT 核心时沿用原模型的校正预算，原有 DCT 代码和配置没有被这次默认值调整修改。

```text
python -m pytest tests/test_transport_plugin_core.py tests/test_transport_plugin_reconstruction.py tests/test_transport_plugin_adapters.py tests/test_transport_plugin_native.py tests/test_transport_plugin_experiment_plan.py -q
```

本机最终检查为 **121 passed**，包含 CPU BF16 与 CUDA FP16。纯 CPU 环境运行上面的检查时追加 `-k "not bilinear"`，排除上游 MCAT 必须使用 CUDA 的 bilinear 接口。默认模型预设使用 concat，可在 CPU 构造。

## 7. 服务器取用

本轮交付在 `codex/v313-transport-plugin` 分支，基于已推送的三解码器版本。可以在服务器现有仓库中获取并创建一个单独目录：

```text
git fetch origin codex/v313-transport-plugin
git worktree add ../DCT-Reg-transport-plugin FETCH_HEAD
```

随后进入新目录使用构造预设和实验计划工具。该方式不切换现有实验目录，也不启动任何任务。先核对协议与输入，再由实验负责人接入原生训练器并开始匹配训练。
