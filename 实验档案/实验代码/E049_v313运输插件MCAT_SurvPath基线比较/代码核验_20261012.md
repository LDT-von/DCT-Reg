## 臂定义一致性核查

| 臂名 | enabled | plan_mode | reconstruction | decoder_mode |
|---|---|---|---|---|
| `native` | False | learned | False | — |
| `independent` | True | independent | False | — |
| `learned` | True | learned | False | — |
| `independent_three_decoders` | True | independent | True | separate |
| `learned_three_decoders` | True | learned | True | separate |
| `learned_shared_decoders` | True | learned | True | shared |

**一致性**：`ARM_DEFINITIONS` 在 `schedule_core.py`、`worker.py`、`model.py` 三处保持同步。

## 容量等价核查

- `independent` vs `learned`：结构完全相同，仅 `plan_mode` 不同（参数数量一致）
- `independent_three_decoders` vs `learned_three_decoders`：结构完全相同，仅 `plan_mode` 不同
- `native`：插件关闭，主干结构同 `learned`，无插件参数活跃

## 关键风险

1. **MCAT 原生损失**：MCAT 使用事件分层 NLL，需要在 `worker.py` 中显式实现，不能直接复用 DCT 的 `train_runner.py` 损失函数。需要确认是否有现成的 MCAT 损失实现，或需要额外编写适配层。
2. **SurvPath 原生损失**：SurvPath 使用负对数似然，同样需要独立实现。
3. **训练循环劫持**：E048 直接 patch `train_runner` 的 `get_model`/`get_split`，E049 采用相同策略，但 MCAT/SurvPath 的原生 `forward()` 输出格式不同（DCT 输出 `logits`，MCAT 输出 `(hazards, survival, Y_hat, attention_dict)`），需要适配 `evaluate()` 函数的结果提取。
